# Phase C（文字起こし・履歴）実装計画

- 根拠: 詳細仕様書 3 章（1 ジョブずつ・録音優先）、7 章（Processing の状態・再開・キャンセル・Revision）、8 章（文字起こし）、15 章（保存構造・`jobs` / `transcript_revisions` / `segments`）、18 章（UI-03・UI-04・UI-06）、19 章（STT-001〜003）、20 章（NFR-06）、22 章（CER・AT-06、07、26）
- 前提: Phase B の受入試験に合格（`docs/phase-b-report.md`）。whisper.cpp b5454（CPU 版）と `ggml-small.bin` は導入済み（`docs/environment-lock.md` 4・5 章）

## 0. 決定事項（2026-11-01、利用者と合意）

- **CER の評価音声は、私が作る会議風の原稿 3 本（人名・数字・期日を含む、各約 10 分）を利用者が読み上げて録音する**。実装の後半（C5）で、利用者の都合のよいときに行う
- **`ggml-medium.bin`（約 1.5 GB）と Silero VAD モデル（数 MB）をダウンロードしてよい**。保存先は `%LOCALAPPDATA%\VoiceJournal\models`、SHA-256 を `environment-lock.md` に記録する
- **録音中は文字起こしを一時停止する**。録音を始めたら実行中の whisper を止め、録音が終わったら再開する（3.6）

## 1. ゴールと完了条件

録音が終わったセッションを、音源ごとに文字起こしして時刻順にまとめ、画面で読み・聞き直し・直せるようにする。原文は不変で、修正と再認識は新しい Revision として残す。

**完了条件**（詳細仕様書 23 章）: AT-06、07、26 に合格し、性能（NFR-06）と CER を実測する。

| ID | 内容 | 確かめ方 |
|---|---|---|
| AT-06 | 同じ音声を small と medium で処理。原文と区間を保存し、モデルの hash を記録。CER と所要時間を報告 | 実機（読み上げ 3 本） |
| AT-07 | 原文を修正し、区間を再認識。原文は不変、修正 Revision が増え、根拠参照が旧版か新版か明確 | 自動テスト＋実機 |
| AT-26 | 設定を変えて同じ原音から再処理。入力・モデル・設定・成果物の Revision を追跡でき、旧承認は必要に応じ失効 | 自動テスト＋実機 |
| NFR-06 | small（CPU）で 30 分の日本語音声を 30 分以内 | 実機（読み上げ 3 本をつないだ約 30 分） |
| CER | 静かな日本語 10 分×3 本で 15% 以下（初期基準） | 実機（読み上げ 3 本） |

## 2. 範囲

**含む**

- STT 用の派生音声: 音源ごとに原音チャンクをつなぎ、16kHz・16bit・mono の WAV を作る。開始オフセットや切断の空白は無音で埋め、セッションの時刻と一致させる（無音を詰めない）
- 長時間の分割: 30 分ごと・境界の前後 2 秒の重なり。セグメントの中点が属する区間を採用し、境界で切れた文は両方を残して「要確認」にする
- whisper.cpp アダプター: 登録した実行体とモデルの hash 照合、`ArgumentList` での起動、進捗の読み取り、タイムアウト、キャンセル（5 秒待って自分が起動したプロセスだけ終了）、録音中の一時停止、JSON 出力を内部スキーマへ変換
- VAD（Silero、whisper.cpp 内蔵の `--vad`）: 認識する範囲の選択だけに使い、時刻は元の音声の時刻で保存する
- 原文と修正の分離: `transcript.raw.json`（不変）、人手修正の Revision、閲覧用の `transcript.md`
- 品質フラグ: 無音、反復（幻覚の疑い）、短すぎる発話、区間境界、欠損区間との重なり、利用者修正
- 区間の再認識: 選んだ区間だけを、同じまたは別のモデル・設定で認識し直し、新しい Revision にする
- 再処理（AT-26）: 設定を変えて同じ原音から新しい原文 Revision を作る。入力 hash・モデル hash・設定 hash・成果物 hash を残す
- ジョブ: 1 つずつ実行するキュー、`jobs` 台帳、アプリが落ちても完了した区間から再開、録音中の一時停止、キャンセル
- 録音後の自動キュー投入（録音画面に「保存後に文字起こし」のチェック。既定はオン）
- 画面: ライブラリに処理状態、文字起こし画面（UI-06: 音源ラベル・時刻・本文・品質フラグ・修正履歴、区間再生、編集、区間再認識）、処理状況（UI-03 の最小版）、STT の設定（モデル・VAD・スレッド数）
- 評価の道具: 原稿 3 本、CER の計算（正規化規則を固定）、`scripts/Test-PhaseC.ps1`

**含まない（後のフェーズ）**

- LLM による整理（Organizing 以降の工程。Phase D）。Phase C の処理は「文字起こし済み」で止まる
- 用語辞書（モデルへのヒント `--prompt` として使う部分は、入口だけ用意して Phase D 以降で判断）
- 話者の推定、ミックス WAV、GPU（Vulkan）での実行（Phase H）
- 承認の失効そのもの（承認は Phase D 以降で生まれる）。Phase C では、失効を判断できるだけの系譜（どの原文 Revision から作られたか）を残す

## 3. 設計の要点

### 3.1 プロジェクトへの配置

| 置き場所 | 内容 |
|---|---|
| Core | 文字起こしのモデル（セグメント・Revision・修正・品質フラグ）、分割計画と中点による統合、反復の検出、Processing の状態遷移、ジョブの手順（区間ごとの再開判定）、CER の計算。whisper の起動や音声変換は `ISttEngine`・`ISttInputBuilder` などのインターフェース越しに扱う |
| Infrastructure | 16kHz 変換（NAudio の WDL リサンプラー）、whisper-cli のプロセス管理と JSON の読み取り、モデルの登録と hash 照合、空きメモリの確認、DB のマイグレーション（版 2） |
| App | ライブラリの処理状態、文字起こし画面、処理状況、STT 設定、録音画面のチェックボックス、キューの常駐サービス |

### 3.2 保存構造

詳細仕様書 15.1 の例を元に、原文の Revision を複数持てるよう次の形にする。

```text
sessions/yyyy/MM/<session-uuid>/
  manifest.json                     # 録音（Phase B のまま）
  derived/stt-input/<input-hash>/   # 再生成可能。16kHz mono の分割 WAV と、作り方（ゲイン・リサンプル設定）
    mic/part-0001.wav ...
    loopback/part-0001.wav ...
    input.json
  stt/native/<job-id>/              # whisper の生出力・引数・stderr・版。版に依存
  transcripts/
    rev-0001/transcript.raw.json    # 原文（不変）。入力・モデル・設定の hash を含む
    rev-0001/transcript.raw.txt     # 音源・時刻つきの原文
    rev-0002/transcript.edited.json # 人手修正。親 Revision と元の segment_id への参照
    rev-0003/transcript.raw.json    # 設定を変えた再処理（AT-26）。親は持たず、入力 hash で同じ原音と分かる
  transcript.md                     # 閲覧用。最新の Revision から作る
```

- 正本はファイル。DB の `jobs`・`transcript_revisions`・`segments` は索引で、ファイルから作り直せる（Phase B と同じ考え方）
- Revision の番号はセッション内で増やすだけで、書き換えない。どの Revision が「現在の版」かは、最新の修正または利用者が選んだ版

### 3.3 STT 入力の作り方

- 原音チャンクを `StartMs` の順につなぐ。トラックの開始前や切断の空白は無音で埋め、16kHz の派生音声の 0 ms がセッションの 0 ms と一致するようにする。こうすると whisper の時刻にずれの補正なしでセッションの時刻になる
- 2ch はダウンミックス（平均）。48kHz → 16kHz は WDL リサンプラー（決定的な結果になる）
- ゲイン: raw モードのマイクは音量が小さいため、トラック全体のピーク（瞬間的な雑音を避けるため 99.99 パーセンタイル）を −3 dBFS に合わせ、上限 +30 dB とする。効果は C5 で CER を比べて確かめ、効かなければやめる。設定値は `input.json` に記録する
- 入力 hash = 使った原音チャンクの SHA-256 の並び＋変換設定。同じなら作り直さない

### 3.4 whisper.cpp の実行

```text
whisper-cli.exe -m <model> -f <part.wav> -l ja -oj -of <prefix> -t <threads> -pp [--vad -vm <silero>] 
```

- 実行体とモデルは、設定に登録したパスで、起動前に SHA-256 を照合する（不一致は STT-001）。shell は使わない
- 標準出力と標準エラーは非同期で回収し、`progress = N%` から進捗を出す。区間ごとの上限は 60 分（設定可）
- 成功の判定: 終了コード 0、JSON が存在して読める、各セグメントが 0 ≤ start < end ≤ 区間の長さ
- 起動前に空きメモリを確認する。足りなければ、LM Studio のモデルをアンロードするよう案内する（無断でアンロードしない）
- whisper の JSON はそのまま契約にせず、内部のセグメント（`segment_id`・`source`・`start_ms`・`end_ms`・`text`・`quality_flags`・`native_ref`）に変換する。信頼度は返らないので作らない
- VAD を使ったときの時刻が元の音声の時刻で返るかは、C2 で「既知の位置に声を置いた音声」で確かめる。ずれる場合は VAD を使わず、無音検出を自前で行う

### 3.5 ジョブと再開

- 状態は Queued → Normalizing → Transcribing → Transcribed（Phase C の終点）。例外は Failed / Cancelled。Phase D で Transcribed の後に Organizing 以降をつなぐ
- 再開の単位は「音源 × 30 分区間」。区間の結果（生 JSON と変換後のセグメント）を hash つきで保存し、アプリが落ちたら、検証できる区間は使い回して残りだけやり直す
- 試行回数とエラーコードを残す。失敗した区間だけをやり直せる（STT-002）。無音で何も認識されない区間は「未認識」とする（STT-003）
- キャンセルは作業中の成果物だけを捨てる。原音と確定した原文 Revision は残す

### 3.6 録音中の一時停止

- 録音を始めたら、新しいジョブを始めない。実行中の whisper は**プロセスのスレッドを一時停止**して CPU を空け、録音が終わったら再開する（途中までの計算を失わない）
- 一時停止できなかったときは、その区間の whisper を止めて、録音後にその区間だけやり直す
- 一時停止している間は区間のタイムアウトを数えない。一時停止中も whisper はメモリを持ったままなので、録音開始時の空きメモリ確認では、その分を差し引いて考える

### 3.7 修正と再認識

- 修正は「元の segment_id → 新しい本文」の差分として新しい Revision に保存する。原文の Revision は変えない。「原文へ戻す」も新しい Revision
- 区間の再認識は、選んだ範囲（前後 1 秒を足す）の 16kHz 音声を切り出して whisper にかけ、結果を新しい Revision に入れる。モデル・設定・元の範囲を記録する
- Phase D で記録や候補が根拠として segment を参照するときに、どの Revision の segment か分かるよう、参照は「Revision ＋ segment_id」の組にする（AT-07 の「根拠参照が旧版か新版か明確」）

### 3.8 CER の計算（規則を固定）

- Unicode NFKC で正規化し、句読点・記号・空白を除く
- 数字の表記をそろえる: 漢数字の数（「二十五」「三千」など）を算用数字に直す。「一人」「一つ」のような慣用的な語は直さない例外表を持つ
- 編集距離 ÷ 正解の文字数。規則は `tests` に例つきで固定する

## 6. リスクと対策

| リスク | 対策 |
|---|---|
| PC 内部音声のトラックは無音が長く、whisper が無音から文を作る（幻覚） | VAD で認識範囲を絞る。反復や無音区間の文に品質フラグを付け、画面で重点表示する |
| VAD を使うと時刻が元の音声とずれる | C2 で既知の位置の音声で確かめる。ずれるなら自前の無音検出に切り替える |
| medium が遅すぎる（30 分の音声に 30 分以上） | medium は品質比較用（NFR-06 は small の目標）。所要時間をそのまま報告し、既定は small のまま |
| LM Studio のモデルが常駐していてメモリが足りない | whisper 起動前に空きメモリを確認し、アンロードを案内する。無断でアンロードしない |
| 一時停止したプロセスが録音中にメモリを持ち続ける | small で約 1 GB、medium で約 2 GB の見込み。C2 で実測し、問題があれば止めてやり直す方式に切り替える |
| 固有名詞の誤り（Phase A で「田中さん」→「田舎さん」など） | medium と比べる。用語辞書のヒント（`--prompt`）は Phase D 以降で判断 |
| 8 時間の録音で、派生音声と処理時間が大きくなる | 派生音声は 1 時間・1 音源あたり約 115 MB。30 分区間ごとに作り、処理が終わった区間は再生成できるので、容量が足りないときは削除できる（`cache` 扱い） |
