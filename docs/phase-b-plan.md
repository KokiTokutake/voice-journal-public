# Phase B 計画 — 録音・保存

- 作成日: 2026-11-01
- 根拠: 詳細仕様書 6 章（録音仕様）、7 章（Capture の状態）、15 章（保存構造・DB）、18 章（UI-02）、19 章（CAP / FS / REC）、22 章（AT-01〜05、19）
- Phase A の知見: `docs/environment-lock.md` 9 章

**決定事項（2026-11-01、利用者確認済み）**

- マイクの既定は **raw モード**。設定で通常モードにも切り替えられる
- **CommunityToolkit.Mvvm** と **Microsoft.Extensions.DependencyInjection** を追加する
- 長時間の受入試験（両方 60 分、8 時間）は **Phase B の最後（B6）** に実機で行う

## 1. ゴールと完了条件

**ゴール**: 文字起こしや LLM が未設定でも、マイク・PC 内部音声・両方を安全に録音し、原音を失わずに保存・一覧・回復できる。

**完了条件**（詳細仕様書 23 章）: AT-01〜05、AT-19 の録音部分に合格し、原音だけでもアプリとして使える。

| 受入 | 内容 | 確認方法 |
|---|---|---|
| AT-01 | マイク 60 秒。原音が再生でき、経過時刻と長さの差 100ms 以内 | 実機（利用者が読み上げ） |
| AT-02 | 選択した出力先の音を内部録音。無音を正常に扱う | 実機（TTS を自動再生、Phase A と同じ方式） |
| AT-03 | 両方 60 分、時刻写像あり、ずれ 100ms 以内 | 自動テスト（模擬音源）＋実機の長時間試験 |
| AT-04 | 無音、マイク権限拒否、開始時の片方失敗 | 自動テスト＋実機 |
| AT-05 | 両方 8 時間、チャンク切替、未通知ドロップ 0、メモリが時間に比例しない | 自動テスト（模擬音源を高速再生）＋実機の 8 時間試験 |
| AT-19 | `.partial` 途中・容量不足・手動スリープ・USB 切断 | 自動テスト（強制終了・容量不足の模擬）＋実機 |

## 2. 範囲

**含む**

- 録音 3 モード（マイク／PC 内部音声／両方）、デバイスの明示選択、開始時に既定デバイスを解決して固定
- 原音のチャンク保存（取得形式のまま WAV、5 分ごとに確定、`.partial` と 1 秒ごとのサイドカー、SHA-256）
- manifest.json（セッション・トラック・チャンク・イベント）と SQLite の索引（sessions / audio_tracks / audio_chunks / audio_events / workspaces / schema_migrations）
- 時刻管理（単調時計、トラックごとの開始オフセット、ループバックの無音補完、欠損イベント）
- 有界キュー（音源ごと 2 秒）と専用ライター、溢れたら欠損を記録して安全停止
- デバイス切断（一部音源停止、残りは継続、明示操作で再接続）、スリープ抑止と復帰後の中断扱い、空き容量の確認
- 起動時の回復（`.partial` の検査と recovered WAV の作成）
- WPF: 画面の枠、UI-02 録音画面、最小限のライブラリ（一覧・欠損警告・フォルダーを開く・再生）、起動時の回復案内、録音中に閉じるときの確認

**含まない（後のフェーズ）**

- 文字起こし・STT 用 16kHz 派生ファイルの作成（Phase C。ただし派生処理を差し込める形にしておく）
- ミックス WAV（任意の派生物。Phase C 以降）
- 設定画面の全項目、初回セットアップ（UI-01）の接続テスト部分

## 3. 設計の要点

### 3.1 プロジェクトへの配置

| 置き場所 | 内容 |
|---|---|
| Core（Windows 非依存） | セッション・トラック・チャンク・イベントのモデル、Capture の状態遷移、manifest の読み書き、**WAV チャンクライター（自前実装）**、サイドカー、`.partial` 回復、録音パイプライン（キュー・ライター・切替・停止手順）、時刻写像。外部要素は `IAudioSource`・`IMonotonicClock`・`IDiskSpace` などのインターフェース越しに扱う |
| Infrastructure | NAudio 3 の `WasapiRecorder` を使う音源アダプター、デバイス列挙と切断通知（`IMMNotificationClient`）、SQLite とマイグレーション、スリープ抑止（`SetThreadExecutionState`）と電源通知、空き容量 |
| App | WPF の画面と ViewModel |

WAV ライターを Core に自前で持つ理由は、回復処理がヘッダーとサイドカーを正確に解釈する必要があることと、模擬音源で全経路を自動テストするため。形式は取得した `WaveFormat` をそのまま書く（float は float のまま、WAVE_FORMAT_EXTENSIBLE を保持）。

### 3.2 録音パイプライン

```text
WasapiRecorder のコールバック ──コピー──▶ 有界キュー（音源ごと 2 秒） ──▶ ライタースレッド
   （推論・DB・ファイル操作をしない）                                       ├ .partial へ追記
                                                                          ├ 1 秒ごとにサイドカー（frame_count）
                                                                          ├ 5 分ごとにチャンク確定 → SHA-256 → .wav へ改名
                                                                          └ manifest をアトミックに更新（一時ファイル → 置換）
```

- コールバックではバッファをプールから借りてコピーし、キューに入れるだけにする。レベル表示用のピーク値もここで軽く計算する
- キューが溢れたら黙って続けない。ドロップ範囲を `audio_events` に記録し、録音を安全停止して「音声欠損あり」にする（CAP-003）
- 停止手順: 新規取得の停止 → キューを吐き出す → 全ライターを確定 → manifest 保存 → 録音確定。停止の連打は同じ要求として扱う
- 「準備中」は最初のパケットを受け取るまで。受け取る前に「録音中」と表示しない

### 3.3 時刻と無音

- 基準は単調時計（`Stopwatch`）。開始時に UTC 時刻とタイムゾーンも記録し、Windows の時刻変更の影響を受けない
- ループバックは再生がない間パケットが来ないため、経過時間に合わせて無音を補う（Phase A で動作確認済み）。補った区間は `loopback_silence` イベントとして記録し、デバイス障害とは区別する
- `WasapiRecorder` が返すデバイス位置は単位が未確認（Phase A の持ち越し）。B3 で調べ、使えるならクロック補正に使う。使えなければ経過時間を基準にする

### 3.4 マイクの録音モード

- Phase A の比較結果（raw モードで CER 0.158 → 0.079）から、**既定を raw モード**にする（決定済み）。設定で通常モードにも切り替えられる
- raw モードは音量が小さいので、レベル表示はそれを前提に目盛りを調整する。原音は加工せず、STT 用の派生ファイルだけを正規化する（Phase C）

### 3.5 デバイス・電源・容量

- 開始時に「既定デバイス」をデバイス ID に解決して固定する。`WithDefaultDeviceStreamRouting()` は使わない（仕様の「無断切替しない」に合わせる）
- 両方モードは、開始時に両方の音源が取れなければ開始しない
- 切断時はそのトラックを閉じて「一部音源停止」にする。残りは継続し、警告と欠損開始時刻を表示する。再接続は利用者の操作で新しいチャンクとして始める
- 録音中はシステムの自動スリープを抑止する（画面の消灯は妨げない）。サスペンド通知では可能な限り確定し、復帰後は「中断」として再開か終了かを選ばせる
- 開始前に空き容量を確認し、録音中も定期的に確認する。閾値を下回ったら安全停止する（FS-001）。音声の自動削除はしない

### 3.6 保存構造と DB

- 保存先は `%LOCALAPPDATA%\VoiceJournal\Workspace\sessions\yyyy\MM\<session-uuid>\`。構成は詳細仕様書 15.1 のとおり
- 原音の正本はファイルと manifest。DB は索引として、manifest から作り直せるようにする
- DB は Phase A で確認した設定を使う（WAL、`foreign_keys=ON`、`synchronous=FULL`、`busy_timeout=5000` と `Default Timeout` をそろえる）。最初のマイグレーションで Phase B に必要な表だけを作る
- 音声コールバックやライタースレッドから DB を触らない。DB の更新はチャンク確定や状態変化のときに、別スレッドからまとめて行う

### 3.7 起動時の回復（REC-001）

- 状態が Recording / Stopping のまま残ったセッションを探す
- `.partial` は、サイドカーの frame_count・実サイズ・block_align の整合を確かめ、読める範囲だけを別の recovered WAV に保存する。元の `.partial` は残す
- セッションは「中断」にし、「最後の最大 5 分のチャンクに未確定のデータがあり得る」と表示する

## 6. リスクと対策

| リスク | 対策 |
|---|---|
| ループバックの無音補完と実際の音のずれが長時間で積み上がる | B2 の模擬試験で誤差を測る。B3 でデバイス位置が使えればクロック補正に使う。AT-03 の実機 60 分で確認 |
| raw モードに対応しないマイクがある | 開始に失敗したら通常モードでの開始を案内する（自動では切り替えない） |
| 8 時間録音でのメモリ増加 | バッファをプールで使い回す。B2 で 8 時間相当を高速に流してメモリを測る |
| 電源断ではサイドカー以降のデータが失われる | 仕様どおり「末尾 2 秒以内の損失」は正常な強制終了だけを目標にし、電源断は保証しないと表示する |
